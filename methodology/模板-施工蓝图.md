## 一、施工目标

- 核心问题（带 `file:line` 根因）

- **功能级完成清单（v3.0 强制要求：七列，含 `档` 列）**：

| 编号 | 功能 | 自动验证 | 人工验证类别 | **档** | 人工验证编号 | 完成状态 |
|---|---|---|---|---|---|---|
| F-01 | <真实外部渠道功能> | A-01 | C 类（真实环境） | **M 必验** | H-01 | ⬜ 未开始 |
| F-02 | <界面 / 交互功能> | A-02 | B 类（人眼确认） | **O 选验** | H-02 | ⬜ 未开始 |
| F-03 | <内部逻辑> | A-03 | 无（纯机器逻辑） | — | — | ⬜ 未开始 |

> **`档` 列怎么填**（规范 §4.1.0）：问「这件事的正确答案，机器能不能自己判定」。

## 三、前置条件与停止条件

- 前置：可执行命令 + 期望值；不满足则**不得开始**

  ```powershell
  Select-String -Path "..\task-<任务名>\PHASE-<n-1>-完成报告.md" -Pattern '^\s*-\s*\[ \]|\|\s*\[ \]\s*\|'
  # 期望：无输出
  ```
- ★ **基线已读且新鲜**（规范 §6.1）：
  ```powershell
  Get-Content ..\task-<任务名>\BASELINE.txt      # 期望：7 个字段都在，且 head / node 与本机一致
  ```
  🔴 **本节的前置条件里不写任何硬编码数字** —— 数字只在 `BASELINE.txt` 里定义（规范 §6.1.1）。
  要判它是否过期，原样抄这两条**固定编号**判据（规范 §6.1.5；它们**不占用本文的 `A-nn` 序列**）：
  - **BASE-01 自洽**：`head` 是真实提交且不超前于 `HEAD`
  - **BASE-02 新鲜度**：受测路径在 `head` 之后未被提交改动，**且工作区在该路径下干净**（`git log` + `git status --porcelain`；两者都必须为空）
- 停止：出现什么情况**立即停止并报告**，并写清「为什么必须停」

## 五、人工环节 ★（人必须做的部分；含功能级与 Phase 级验收）

> **一个环节一行，全部写进 `../task-<任务名>/HUMAN-人工验证台账.md`**（规范 §4.1.2 的**七列表**）：
> 前四列（编号 / 类·档·时点 / 要验什么 / 期望值）由 **agent 预填**，人只填后三列。**本蓝图不另开作业单或回执文件。**

- **H-A 阻塞性拍板**（开工前；未答复不得开始 —— 同时登记进 §三 前置条件；台账里以 `[ ]` / `[x]` 表达）
- **H-F 功能级人工验收**（**仅 M 档**在每个功能实现完成后即时验证；**O 档不阻塞出口**，可在本 Phase 收尾时一并扫一眼或直接由机器判据关闭）
- **H-B 完工评审**（本 Phase 的总体退出条件；人只做判断项，**不重算脚本能算的数**）
- **H-C 待验项登记**（本 Phase 验不了的，追加进 `HUMAN-人工验证台账.md` 的一行）
- 本 Phase 明确**不需要**人做的事（防止让人做无用功）

> 四条纪律：人只做机器做不了的事；期望值由 agent 预先算出；验不了就明说并登记；
> **不得为了凑内容发明无用的人工步骤**（让人去点一个跑不起来的程序是负价值）。
> 逐条写法与判据设计八条硬要求见规范 §4.1；**验完在台账里就地把那一行回填**（规范 §4.1.3）。

## 六、验收测试

- A1…An：每条 → 一条可执行命令 → 期望输出 → **失败处置**
- 判据必须是**充分的**，不能只是**启发式的**（见规范 §7.1）
- ★ **退化判据必须写成差集**（规范 §6.1.3 用法 2 / §6.2.3）：`本次失败集合 − 基线失败集合 = 空集`；
  标量三看 `suites ≥ 基线` / `cases ≥ 基线` / `exit = 基线`，**`exit=0` 单独没有判别力**
- 「不算失败」的情形必须提前写明（时点断言 / 有意保留项 / 外部增长量）
