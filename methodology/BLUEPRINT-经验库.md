# 蓝图经验库（精简版）

> **本文件是唯一的经验库。** 旧版三份（通用 / 具体坑 / 全量台账，合计约 33 万字符）已合并、去重、重编号为本文件。
> **读者**：写蓝图的人 / 执行蓝图的人 / 复核的人——三者共用同一份，不再按角色拆读。
>
> **规模**：**111 条**（P 判据 22 / B 边界 10 / V 验证 13 / C 变更 27 / R 报告 15 / H 人在环 8 / I 基础设施 16），约 2 万字符。
> 旧版三份合计约 **19.5 万字符**——本版压缩到约 **1/10**，且不丢可执行结论。
>
> **怎么用**：**整份通读一次**（约 15 分钟），之后只在写判据、写蓝图 §六、写完成报告自检时回来查。
> 实测教训：**agent 在任务中途不会回头翻库**——所以本库必须小到「能一次读完并记住形状」，而不是大到「能查到一切」。
>
> **编号规则**：字母表示**失效类别**，序号稳定不变。蓝图与报告交叉引用一律用这套编号；
> 每条在编号后括注旧版键号（如 `P1 ⟨C7⟩`），便于从旧文档迁移引用。
>
| 前缀 | 类别 | 一句话 |
|---|---|---|
| **P** | 判据（Predicate） | 这条验收到底能不能证明我想证明的事 |
| **B** | 边界（Boundary） | 一个语义在系统里有几处载体 / 完整性单位是什么 |
| **V** | 验证（Verify） | 尺子、对照物、数据源、证据本身可不可信 |
| **C** | 变更（Change） | 改动顺序、传播面、破坏性动作、回滚 |
| **R** | 报告（Report） | 数字、文档、产物怎么留下可复核的痕迹 |
| **H** | 人在环（Human） | 哪些必须人做、哪些可以不做 |
| **I** | 基础设施（Infra） | 命令与工具的行为坑（**L 级，换栈必须重新实测**） |
>
> **每条三段**：反例（会怎么做错）/ 为什么会错（机制层根因）/ 怎么才对（可执行）。
> **旧版的「出处」列不再保留**：本版只留**能直接改变行为**的部分；需要考古时查 `BLUEPRINT-经验库-全量台账.md`（保留，不参与日常读取）。

## §0 六问自检（写任何判据、蓝图 §六、完成报告 §四之前必答）

这六句是本库的**压缩形式**——记不住 70 多条时，记住这六句。

1. **两个世界问**：这条判据，在「我做对了」和「我根本没做」这两个世界里，会不会给出**同一个结果**？（→ P1 P2 P7 P13 P16 P21）
2. **作用域问**：这条判据**扫的范围**，是不是**恰好等于**它想证明的那件事的范围？多扫了假红，少扫了假绿。（→ P3 P4 P9 P10 P20 B1）
3. **前提问**：这条结论依赖三样东西——**尺子**（参照物）、**对照物**、**数据源**。这三样**各自被证明过吗**？（→ P17 P18 P19 V1 V11）
4. **此刻问**：我引用的 ref / 行号 / 路径 / 计数，**此刻实测**是什么？「上一个 / 全部 / 目录内的 / 默认的」都随**执行位置**漂移。（→ P5 P6 C18 I2）
5. **两端问**：我写在**字符串里**的契约（类名、路径、通道名、i18n 键、mock 名），**两端都在吗**？一端没了**谁会报错**？答案是「没人报错」→ 它需要一条自己的判据。（→ P14 B3 C24 I14）
6. **守恒问**：我写的这个数是**量级 / 上界**，还是**守恒量**？**数法**是什么？量级不能当判据，上界不能当工作量。（→ P2 P9 C14）

## §1 判据设计（P）

> 一条判据写出来之后，**它自己也要被审一次**：能不能变红、扫的范围对不对、绿色有没有隐藏前提、数字是不是守恒量。

| # | 反例（会怎么做错） | 为什么会错 | 怎么才对 |
|---|---|---|---|
| **P1** ⟨C7⟩ | 用负向断言证明「清理干净了」：`expect(x).not.toContain("[前缀]")` | 负向断言只能证明**某子串不在**，不能证明**结果正确**；部分剥离也能通过 | 完整性用**等值断言**（`x === "111"`）；要判「无残留」就同时判「正文等值」 |
| **P2** ⟨D18⟩ | 把量级写成硬目标：`Test Files 0 failed \| 561 passed (561)` | 只要本阶段新增了测试，数字**必然**变；目标数往往是按计划估的，不是可复现目标 | 硬判据只留**布尔量**（`0 failed` + 退出码 0）；数字改用**加法恒等式**：`562 = 561 + 1`、`5429 = 5403 + 2 + 24` |
| **P3** ⟨D22 / C24⟩ | 判据写「删除 X 后全仓 0 命中」；或「某能力已无调用方」用全仓 grep | **扫过头**：参照模块、证据备份、正在讨论这件事的文档都会命中 → 恒假红。反向则是**少扫**：只搜已跟踪文件的工具看不见未入库的新产物 → 把「已接线」判成「没接线」 | 判据**限定到消费该对象的那一层**，并把**各作用域的命中数逐一列出**（0 / 1 / 4 / 5），让读者看出哪些是噪音 |
| **P4** ⟨C18⟩ | 对活数据断言「全树逐字节不变」 | 判据作用域里混进了与被测操作**无关的活数据**（别的群在聊天）→ 把正常写入记成违规 | 拆三条：① 目标域**逐字节不变** ② 其余**只允许纯追加**（旧内容是新的前缀）③ 无文件被删或变小 |
| **P5** ⟨D19⟩ | 判据里写死 `HEAD~1` / `HEAD^` 代表「上一个基线」 | **相对 ref 的含义随「你站在哪一步」漂移**，而判据文本是静态的 → 同一份蓝图在提交前后跑出两个结论 | 点名**基线是谁**（哈希或 tag）；或给出**提交前 / 提交后两个口径**，两个都要能复现为 0 |
| **P6** ⟨D20⟩ | 把「检查工具报了 N 个问题」当成「总共只有 N 个」 | **fail-fast 的语义是「报告首个失败」，不是「报告全部」** → 规模评估系统性偏小，而规模正是「该不该停下来问人」的依据 | 用**与工具同源**的判据独立**复扫整个扫描面**并打印总数；复扫 > 工具报数时**优先信复扫**；超出阈值 → 停止并交人 |
| **P7** ⟨D21⟩ | 把「全量测试 0 failed」当**自足**判据，不记环境前提 | 有一类用例**真的 spawn 宿主工具链**（跑真 `npm run build`）→ 绿色取决于 PATH 上第一个 `npm` 是否可用。同一提交、同一命令，只调 PATH 就由红转绿 | ① 跑全量前**先记环境指纹**（`where npm` / `npm --version` / `node --version`）写进报告；② 报告的「0 failed」**必须带 PATH 前提** |
| **P8** ⟨D34 / R9⟩ | 把「测试是红的」直接当成「本次改动引入回归」；反过来把「全绿」当成「没问题」 | 验收要证的是**相对基线没有新增失败**，不是全绿；**有意的行为变更**同样让测试变红 | 判据写成**差集**：本次失败集合减去基线失败集合 = 空集，两侧集合**逐条列出**；存量失败单列成表并写「豁免理由 + 何时重评」 |
| **P9** ⟨D30⟩ | 报告写「两语言各新增 150 个叶子键」，不写数法 | 三种数法（叶子键路径 / 键名去重 / 字符串出现次数）都没写明 → 复核实测 121，**不可复现** | 每个计数**写明数法与口径**；硬判据只留布尔量；不可复现的数字要分开写并注明**实质结论是否受影响** |
| **P10** ⟨D31⟩ | 白名单判据只写「允许改动 2 个文件」 | 计数单位没写：按**改动位置**数是 2，按**路径**数是 4；且没说「判据自己要求新增的测试文件」算不算 | 白名单**直接列路径**而不是给个数；必须给数时写清**计数单位**与**是否含判据自身引入的新文件** |
| **P11** ⟨D23⟩ | 把「必须落到 N 类之一」当判据（N 是拍脑袋定的） | 类别是按**当初设想的对象**设计的，实际对象集合更杂 → 要么造假归类，要么判据恒失败 | 判据写成**未归类 = 0**；类别数**允许随对象增补**，但每类必须给齐四件事：放弃什么 / 为什么 / 依据 / 将来怎么恢复 |
| **P12** ⟨D37⟩ | 清单类交付物只写「清单有 79 行」 | 行数相等是**弱判据**：漏一条 + 重一条也能凑出 79 | **三重咬合**：① 机械生成的底稿 → ② 归类（判据 = 未归类 0）→ ③ 文档表格行数 = 底稿条数；三条都**用脚本**跑并输出进报告 |
| **P13** ⟨F17⟩ | 新增一个守卫测试后，**只验证它现在是绿的** | 守卫的价值 = **它能变红**；「现在是绿的」对它是否在守**零信息量**（它可能把自己 mock 掉了） | 对每条守卫做一次**突变验证**：临时破坏被守的实现 → 确认变红 → 还原并核对 blob 哈希逐字节一致 |
| **P14** ⟨D27 / C25 / C32⟩ | 断言里写字符串字面量（已删除的通道名、类名、i18n 键、mock 名） | 断言用**字符串**而非**真实符号**时，被断言对象的消失**不会让断言失败** → 它在守一个不存在的东西 | 让断言落在**可观察产物**上（磁盘行数 / 渲染出的字符串 / 真实符号引用数）；判「无生产调用方」时**排除** `*.test.*` / `__mocks__` / `vi.fn` |
| **P15** ⟨C5⟩ | 直接改实现，改完再补测试 | 无法确认新用例测的是不是**原来那个缺陷** | **先写回归用例 → 确认它在旧代码上必须失败 → 再改实现** |
| **P16** ⟨C29⟩ | 「源码级守卫」测试按字面量在源文件里搜「某写法不得复发」 | 纯文本匹配**不区分代码与注释**；解释这个 bug 的注释里恰好写了同一个字面量 → 假红 | 用**语法树**取真实节点；或把守卫改成行为断言；注释里的示例要改写形态 |
| **P17** ⟨D33⟩ | 在**对照物为空**时执行否定型判据（「它不该说出 X」） | 输入为空 / 通道未激活同样产生否定结果 → **判据与待检机制没有因果绑定**，这是最隐蔽的假通过（报告里表现为一次干净的 ✅） | ① 执行前**先打印被测数据的真实值**，全空则先写入对照物；② 作业单写明「对照物为空时该判据无意义，不得记为通过」；③ 做**反向对照**：把答案本体写进受限侧，另一侧保留同源信息证明对照成立 |
| **P18** ⟨D26⟩ | 不先校准参照物就拿它当尺子（拿一个缺未跟踪文件的快照当基线） | 参照物只覆盖**已跟踪面**，而主体恰是未跟踪工作 → 把应有的新文件误判成「偷加的」 | **先校准尺子再量东西**：① 参照物与物理备份**逐文件比对**并解释差集；② 抽若干条探针**比 blob 哈希**；③ 报告里显式声明「哪个可用 / 哪个不可用 / 为什么」 |
| **P19** ⟨D35 / F22⟩ | 把缓存 / 本地镜像当权威源，结论不带「来源 + 新鲜度」；机制「从未被真实使用过」就宣布落地 | 抓取源优先级是「先本地镜像后上游」，而**「源过期」在判据里没有位置** → 第一次出场就给**假安全**（诚实报告「无新提交」，真相是 77 个提交）。且判据**只在 N=0 分支被跑到过** | ① 结论**同时输出「源」与「新鲜度」**；② 缓存落后就**回源**或把结论降级为**未检查**——不许报「无风险」；③ 退出码携带新鲜度语义；④ **反向探针**：伪造一个上游提交，确认它能报出重叠 |
| **P20** ⟨D29⟩ | 用字面搜索做收尾判据（「台账里不许有『未知』」、全文档搜未勾选标记） | **判据文本与判据对象住在同一份文档里**，作用域没限定 → 判据**命中自己**，要么恒失败要么被放宽到失效 | ① **限定作用域**（只扫「状态」列 / `^\|.*\[ \]` / 指定小节）；② 或改成**结构判据**（状态列取值只允许 ✅ ⏳ 🚫）；③ 命令里显式排除定义它的那一行并写明原因 |
| **P21** ⟨D16⟩ | 把「场景全绿」当作某条路径已被验证 | 验证样本的激活强度不足 → **有内容的路径始终没有内容**，从未被执行 | 覆盖表里**显式登记未覆盖项**并写明替代防线；不要用「总表全绿」掩盖「某路径从未被执行」 |
| **P22** ⟨D13 / F15⟩ | 用代理变量代替语义字段（「本批只有一个人说话」⇒ 私聊） | 代理量与目标语义**不等价**：`人数 == 1` 与「私聊」在群聊场景下不等价 | 判据字段必须**取自语义来源**（`chatType === "private"`）；代理量只能在有**可证明的一一映射**时作快速判据 |

**三种必须提前写明的「不算失败」**（否则要么假红、要么被人为放宽）：

1. **时点断言**：擦除后主体又活动了 → 断言自然失败。写「取值于**动作刚完成的那一刻**」。
2. **有意保留项**：预先声明保留的东西出现在扫描结果里，不算残留。
3. **外部增长量**：别的进程在写（语料、审计行数）→ 给容差，或改成「只允许纯追加」的相对判据 ⟨C18⟩。

## §2 边界与完整性（B）

> 凡「我以为已经处理完了」的地方，先问：**这个语义在系统里一共存在于几处？**

| # | 反例 | 为什么会错 | 怎么才对 |
|---|---|---|---|
| **B1** ⟨C20⟩ | 删除时把「可删清单 / 保留清单」当成**边界证明** | 「清单即边界」是**设计原则**，而原则需要一条断言来证明它成立；清单之外的载体被**缺省保留**却被记成「已决策」 | 凡以清单为边界的系统，**必须有一条断言证明「没有东西落在清单之外」**；清单外的可疑载体列进「疑似残留」清单，不静默保留 |
| **B2** ⟨A1 A2 A10 A26 A27⟩ | 拆字段 / 加参数时只改主路径（写入侧、调用点），不改读取侧、接口签名、**纯转发的门面层** | 结构化字段与正文文本是两个消费面；门面**零逻辑不等于零改动**；可选参数是**丢参载体**（漏传不报错、不会有测试变红） | **同一批次**改完所有消费者；把「re-export 门面」列为**必查项**；结构化字段要么类型层必传，要么在写入函数里对「缺 meta」直接抛错 |
| **B3** ⟨A56 / A57⟩ | 合并时按「官方分支没有这个文件」就删本地入口；UI 重构只保证后端 + 桥存在 | **入口消失不触发任何编译失败** → 留下「半删状态」：面板本体、路由、桥都在，只有入口没了；用户表现为「设置里找不到」 | 能力的完整性单位是**三层：本体 / 路由 / 入口**，处置单位必须与它对齐；维护**「配置项 → 入口」对照清单** |
| **B4** ⟨A55 / D32 / A11⟩ | 把守卫加在**已知的那条调用路径**上；或用计数型判据守敏感数据边界 | 计数型判据只能看见**它枚举过的那几条路径**，对**新增读取路径天然是盲的**。实测：注入层守住（0 次），工具层同一轮把画像原样送出去（各 3 次），而判据 4/1/0/4 全达标 | 对敏感数据建**矩阵判据**（列出全部读取点，逐个断言守卫存在），覆盖**写与读两侧、注入与工具两条路**；每次新增读写入口，**同批次**加一行 |
| **B5** ⟨A47⟩ | 把「删除 N 个测试文件」当**同质动作**按文件粒度执行 | 测试文件的「死」有两种性质：**整文件死**（加载期找不到模块、0 用例）与**部分死**（能加载、一部分用例失去被测对象）→ 净损失 4 条绿色守卫 | 删除**按用例粒度**确认守卫是否仍生效；红用例不等于死文件 |
| **B6** ⟨C16 / A37 / A38⟩ | 依赖函数名承诺的行为（`addUnique` 其实不查重）；假定「保存」是替换 | **命名与行为不一致**——`unique` 只是调用方的期望；保存是**子对象合并**，未出现的字段不会删 | **行为以实现为准**；调用前确认副作用；「保存」语义写进文档；渲染侧与主进程的**有意不一致**要登记，否则后人会来「统一」它 |
| **B7** ⟨A16⟩ | 把「目前没有生产消费者的纯函数」当无用代码删掉 | 「无消费者」被当成「无用」，但它的消费者在**下一阶段**（输入清单里已列） | 按完整规格实现并配用例，**不删**；文档注明「先于消费者的纯函数」以防后人清理 |
| **B8** ⟨A7⟩ | 加隔离维度时只把 scope 用于 **key 拼接** | 把「标识」当成「隔离」；隔离必须体现为**一次真实的过滤 / 断言**，否则对「防漏」零作用 | 在**数据出口**做防御性过滤（`x.scope === scopeId`），让越域数据被挡住 |
| **B9** ⟨D17⟩ | 追求「处处隔离」，把**所有**读取路径都加域过滤 | 隔离的目标是「注入路径不串味」，而**管理 / 导出类读取与注入类读取语义不同** → 面板、导出、全局衰减看不到全量数据 | 显式登记**「有意保留的不隔离点」**清单，每条给「为什么不管」 |
| **B10** ⟨A10⟩ | 重建（重写、搬迁、重算）时只搬主体，不带元数据 | **凡「重建」必须视为「搬迁」**：`metadata.scope` 丢了 → 该条「回流即失踪」 | 重建路径逐项核对元数据字段；把「重建点」作为一类**必查项**列进蓝图 |

## §3 验证与证据（V）

> 结论的效力取决于**没被核验的前提**。这一节全是「尺子坏了」的实例。

| # | 反例 | 为什么会错 | 怎么才对 |
|---|---|---|---|
| **V1** ⟨C14⟩ | 用「数据副本 + 真实代码路径」算 ground truth，但副本只拷了已知文件名 | 副本的**完备性本身就是断言的一部分**：漏拷一个备份文件，对照值就从 3 变成 2，**差点把正确的产品行为记成缺陷** | 整目录拷贝 + 只排除缓存；**凡副本产出的对照值，先证明副本完整**（清单比对 + 抽样哈希） |

| **R6** ⟨D5⟩ | 风险自评写「中等（有完善的测试覆盖 + 向后兼容保证）」 | 把「有测试」当成降低风险的理由，没验证「测试是否覆盖真实链路」 | 风险按**最坏后果 × 检出难度**定，并**注明哪条真实链路没有任何测试覆盖** |
| **R7** ⟨D6⟩ | 活跃度阈值只写「建议考虑加限流（但本阶段不做）」 | 把「功能可用」当目标，没把「活跃场景」这一真实工况写进验收 | **实现可延后，判据不能缺**：蓝图阶段就写明阈值与降级动作并写进验收 |
| **R8** ⟨D11 / D12⟩ | 用例数按「功能点」估（计划 15 条，实际 22 条）；预判「会打破大量整对象断言」却未发生 | 边界是按**失败模式**长出来的，不是按功能点数出来的；预判基于一般经验而非本仓库实际形态 | 施工记录里**显式登记「计划 vs 实际」**；**如实写「预判未发生」**，避免后人把这条预判当已知风险重复投入 |
| **R9** ⟨D1 / C2 / C3 / C10⟩ | 蓝图把「当前格式」示例写成想象的样子；测试夹具手写成生产不产生的格式 | 契约来自**文档示例**而非生产写入函数的产物 → 正则捕获组永不命中、**测试绿了但路径是死的** | **格式示例必须逐字节复制自真实写入函数的实参**；夹具从真实链路抓取或用生产函数生成 |
| **R10** ⟨C4 / E6⟩ | 用「某文件是否存在」判断操作结果 | 该文件是**懒创建**的，直到首次写盘才生成 → 得到「清空失败」的假结论 | 判存在前先确认**创建时机与触发条件**；改判更可靠的事件（初始化日志）或稳态形态（空目录 + 无该文件） |
| **R11** ⟨A52⟩ | 声明的改动面用一句「**只动 X**」概括 | 复核逐类比对实测出 **10 项**非声明改动 → 后人无法据此判断影响面 | 「只动了 X」必须**拆成清单**（逐项定性有无可见影响） |
| **R13** ⟨新增 v3.2⟩ | 把「不许退化」的基线数字**复制进每一份阶段蓝图**（`期望 27 套件 / 572 项`） | 数字有 N 份副本就有 N 个独立漂移源；**后一个 Phase 加了测试但前一个 Phase 的蓝图没改** → 回头跑旧判据**恒红**，执行者去修一个不存在的问题（**P2** 的镜像：那次是恒绿，这次是恒红） | **数字只在一个地方定义**：`task-<任务名>/BASELINE.txt`（`key=value`），蓝图/总蓝图/报告一律**引用**。蓝图里**不出现硬编码数字**，判据写成「读基线 → 比大小」 |
| **R15** ⟨新增 v3.3⟩ | 并行时把 workspace 里测出的数写回 `BASELINE.txt` | 两个 Phase 各加测试，各自只能看见**自己那一半**。实测：主仓 3、worktree 2、合入后 4 —— **三个不同的数**。写回去就把主仓基线改成「只看得到一半」的数 | workspace 里的 `BASELINE.txt` **只读**；局部实测值记进并入清单（`AD.md`）。主仓的基线**只在并入后由撰写者改**，且**必须重测** —— 合入后的数不等于任何一边 |
| **R14** ⟨新增 v3.2⟩ | 把基线文件的判据写成「`head` **恒等于** `git log -1`」 | 基线文件自己也要提交，于是「测 → 写文件 → 提交」的下一秒就**恒红**；而唯一解法是**手改 head** —— 判据把执行者逼进它自己禁止的那个坑 | 判据改成**三段**：① `head` 是真实提交（`git cat-file -e`）且**不超前**于 HEAD（`merge-base --is-ancestor`）；② **受测路径**在 `head..HEAD` 内未被提交改动；③ **工作区**在该路径下干净（`git status --porcelain`）—— 只查提交历史会把「改了但没提交」判成新鲜 |
| **R12** ⟨F10⟩ | 收集排查素材时直接打印配置文件并原样粘贴进报告 | 报告里带出账号、token | 敏感信息打码；固定「日志收集四件套」：关键日志末尾若干行 + 控制台若干行 + **脱敏**配置 + 复现步骤 |

## §6 人在环（H）——**必验 / 选验 两档**

> **为什么分两档**：旧版把「每个独立功能都要人工验收」写成一刀切，实际会把吞吐锁死。
> 真实的分界线不是「功能大小」，而是：**这件事的正确答案，机器能不能自己判定？**

### 6.1 两档定义

| 档 | 判据（问自己） | 处置 |
|---|---|---|
| **必验 M** | 这个结论**必须有人看到一个真实结果**才能成立吗——真实外部渠道、真实设备、真实账号、真实支付、真实用户视角的「能不能用」 | 登台账 `H-nn`，**未闭合不得宣告完成**；验不了 → 转 BACKLOG |
| **选验 O** | 机器判据已经能给出同等强度的结论，人只是「再确认一眼」 | 台账里登记为 `O` 档、**不阻塞出口**；人不看就由机器结论关闭，并在报告里注明「由 A 类判据关闭」 |

**默认 O 档。** 把它升成 M 档必须写一句理由（「机器判不了，因为……」），否则不许升。

### 6.2 硬规则

| # | 规则 |
|---|---|
| **H1** | **agent 自测通过不等于功能完成**——但这条只对 **M 档**成立。O 档由机器判据关闭是合法的，且必须在蓝图里写明「本功能不需要人工验收，理由：……」 |
| **H2** | **C 类（真实渠道 / 外部服务 / 真机）一律 M 档**，且必须在**真实目标环境**验，不许用 Mock、模拟消息、API 自测代替 |
| **H3** | **人工台账是唯一载体**：`HUMAN-人工验证台账.md`，**一个环节一行**，验完**就地回填那一行**。不新建作业单、回执、功能验收报告等任何平行文件 |
| **H4** | **期望值由 agent 预先算出**（真实代码在数据副本上跑一遍），不许让用户猜；前四列必须 agent 预填完毕，该行才允许出现在台账里 |
| **H5** | **人只做机器做不了的事**：产品取向、视觉 / 交互确认、文案可读性、真实环境端到端。**不要让人重算脚本能算的数字** |
| **H6** | **对照物先就位**：否定型判据在对照物为空时通过得毫无意义 ⟨P17⟩；台账要写明「对照物为空时该判据无意义，不得记为通过」 |
| **H7** | **验后复位** ⟨V5⟩；有数据风险的步骤**只验门不执行** ⟨V6⟩ |
| **H8** | **终态只有四种**：✅ 通过 / ❌ 失败（必须附原始证据）/ 🚫 无法验（写清缺什么）/ ⏳ 待人眼。**不允许「未知 / 待定 / TBD」** |

### 6.3 台账形态（**七列**，唯一真值）

| 编号 | 类·档·时点 | 要验什么（点哪里 / 命令） | 期望值（agent 预先算出） | 状态 | 答复 / 结论 · 日期 | 证据 |
|---|---|---|---|---|---|---|
| H-01 | C · M · H-F | 分组 → 项名 → 页面标题（界面原话逐字一致） | 实测数字 / 截图路径 | ⬜ ✅ ❌ 🚫 ⏳ 取一 | 原样抄录答复，人只判 ✅ 或 ❌ | 截图字节数 + sha256；命令 + 输出 |

- **列归属**：`编号 / 类·档·时点 / 要验什么 / 期望值` = **agent 预填**；`状态 / 答复·结论·日期 / 证据` = **人回填**（证据列 agent 可预填初值，人追加）。
- **时点取值**：`H-A` 开工前阻塞拍板 / `H-F` 功能级验收 / `H-B` 阶段完工评审 / `H-C` 欠账登记。
- **只有 H-A 用未勾选标记表达闭合**；其余用**状态列取值**，否则前置检查会误判 ⟨P20⟩。

## §7 基础设施坑（I）——**L 级：结论绑定具体命令 / API，换栈必须重新实测**

> 这一节只保留「换栈之后你还会以同样方式踩到」的部分。**不要把结论照搬到别的技术栈，只把形状带走。**

| # | 反例 | 为什么会错 | 怎么才对 |
|---|---|---|---|
| **I1** ⟨X4 / X8⟩ | 用 `git merge-tree` 输出里的冲突行数当冲突总数 | 实测**恒为 0**（只输出一个树哈希）→ 误判「完美无冲突」，而真实有 46 个；且命令里若带 `-c` 覆盖仓库配置，测的**不是真实合并行为** | 冲突数只能由**真实试合并**得出（独立临时 worktree）；预估命令里不许有 `-c` 覆盖 |
| **I2** ⟨X16 / C24⟩ | 凭记忆写「含未跟踪」的短选项（`git grep -u`） | `-u` **不是** `git grep` 的选项 → 报 unknown switch + 一整屏 usage 把结果淹没 | 用 `--untracked`；**一律用长选项**；写进脚本前先单跑一次 |
| **I3** ⟨C28⟩ | 解析 `git diff --name-status` / `git ls-files` 输出时按 UTF-8 处理 | 非 ASCII 路径拿到**八进制转义** → 与真实路径比对永远不相等（分类静默漏项） | `git -c core.quotepath=false` |
| **I4** ⟨X2⟩ | 把 git 命令的 stderr 用 2>&1 灌进变量 | `warning` 被灌进管道变量，后续 `rev-parse` 报错 | 需要 stderr 就单独重定向到文件；判定用**退出码**而不是「输出里有没有字」 |
| **I5** ⟨X1⟩ | 用 at-括号包住单个分组对象再取 `.Count` 数条数 | 作用在**单个分组对象**上得到的是「含一个元素的数组」→ 结果**恒为 1** | 先包住集合再取 `.Count`；或 `Measure-Object`；数完用已知样本验一次 |
| **I6** ⟨X7⟩ | 用 `robocopy /LOG:` 记日志并以退出码判成功 | 日志**恒为 2 字节空白**（路径上有 Windows 保留设备名吞掉写入）；退出码是**位标志**，9 可能是假警报 | 看汇总的 FAILED / Mismatch 列；避开保留设备名 |
| **I7** ⟨D25 / X3⟩ | 用 `Set-Content -Encoding UTF8` 写**要给别的程序读**的文本 / JSON / 提交信息 | PS 5.1 的 `-Encoding UTF8` **写 BOM** → 下游首行多一个 BOM 字符，正则 / 解析**静默漏掉第一条**；提交信息里的 BOM 会**永久留在 git 历史** | 给别的程序读时用**无 BOM** 写法（`[IO.File]::WriteAllText` + `UTF8Encoding($false)`） |
| **I8** ⟨X18⟩ | 用 `Get-Content`（不带 `-Encoding`）读无 BOM 的 UTF-8 再数行数 | 数字**静默偏小、且每个文件偏得不一样** | 显式 `-Encoding utf8`；行数判据一律指定编码 |
| **I9** ⟨X14⟩ | 给 `git` 一次传**多个 pathspec** | PS 5.1 下**返回 0 条**，看起来像「文件全都不在提交里」 | 逐个单路径查；或用 `--pathspec-from-file` |
| **I10** ⟨X15 / E9⟩ | 假定「文档里逐字写着的命令」在当前机器上一定能跑 | Windows 上 `npx` 会走 `.ps1` 包装器 → 受**执行策略**管辖，Restricted 下直接拒绝，一条命令都没执行 | 开工前置阶段**实测每条判据命令**；不可用就显式调 `.cmd` |
| **I11** ⟨X5 / X9 / X13⟩ | 跑测试时用旧 reporter 名、用 cmd 的 `&` 后台、`Tee-Object` 到**不存在的目录** | 三种都会让测试**根本没跑**却看起来「已经跑了」：reporter 启动失败 / 退出码语义混乱 / 作业立刻非零退出 | 后台作业落盘前先建目录；reporter 名随大版本变，先 `--help` 确认；**用退出码 + 落盘产物双重确认测试真的跑了** |
| **I12** ⟨X11⟩ | 用构建命令的**退出码**判断多入口是否真的产出了全部入口 | 构建 exit 0、刷满产物行，但入口文件一个都没生成 | 判据要落在**产物存在性**上（逐个入口文件 + 大小），不是退出码 |
| **I13** ⟨E10 / X20⟩ | 换依赖版本后只跑 `npm ci` 就认为安装期脚本都跑过了 | `npm ci` **exit 0 且无报错**，但关键二进制缺失 → 应用起不来（症状与「代码坏了」难以区分） | 装完**核对关键产物存在**；查 install-scripts 白名单与真实产物 |
| **I14** ⟨A15 / C8 / C9⟩ | 正则做前缀剥离时用「第一个右方括号」当分隔符、或把贪婪 / 惰性当解法 | 昵称本身可以含方括号 → 剥完剩残片并**污染下游**；「惰性 / 贪婪」只调长度偏好，**不改变候选起点** | 终止符要**锚定到结构性位置**（行尾 / 括号数字之前）用 lookahead；并用**多组真实格式**（含方括号的昵称、无号码、旧记录、带引用）验证 span |
| **I15** ⟨X17⟩ | 用 `if (!obj?.method) return;` 守卫后，在闭包体里再调 `obj.method()` | 同一个函数体内类型检查器也报错——守卫对**可选的属性访问链**不构成收窄 | 取局部常量：`const m = obj?.method; if (!m) return; m()` |
| **I16** ⟨E1⟩ | 直接按文档类型读跨版本 API 的返回值 | 各版本返回类型不统一，**类型声明不足以暴露运行期差异** | 运行期做形态判断再分支 |

## §9 追加规则

**新踩到一条坑时**：

1. **先问它属于哪一节**（P 判据 / B 边界 / V 验证 / C 变更 / R 报告 / H 人在环 / I 基础设施）。
2. **按该节前缀续编**（P23、B11、V13、C27……），**不要重排已有编号**——编号是跨文档引用锚点。
3. **三列都要写满**：反例（具体到命令 / 代码 / 文档措辞）、为什么会错（机制层，**不许写「不小心」**）、怎么才对（可执行）。
4. **同一形状不要再开第二条**：先在本节里找形状相同的条目，**改造它**而不是新增。
5. **只有真的改变行为才收录**。事实性记录（某版本的某个返回类型）写进报告或代码注释，不进本库。
6. **本库上限约 115 条**。超了就先删：删**依赖具体版本 / 项目**的，删**已被更抽象条目覆盖**的。库越大越没人读——**没人读的经验库等于不存在**。
