# 先读这份 · READ AI FIRST

> **本目录 = 方法论本体（`methodology/`）。**
> 它**跨任务复用**：整个文件夹拷到另一个任务旁边，**无需改动即可用**。
> 任务专属的东西（总蓝图、阶段蓝图、完成报告、决策、人工台账）放在**同级的 `task-<任务名>/`** 里——
> 那个目录**不随本包分发**，用本目录的三份模板新建（见 §三.1）。

```
<工作根目录>\
├── methodology\          ← 本目录：规范 / 经验库 / 回写规范 / 三份模板（跨任务复用，共 8 份）
├── README.md              ← 给人读：包结构、四种用法、常见误用（GitHub 首页渲染的就是这份）
├── 投喂说明-先读我.md     ← 给人读：可直接粘贴给 AI 的开场话术
└── task-<任务名>\        ← 你自己的任务目录（本包不附带；用 §三.1 新建）
                            总蓝图 / 阶段蓝图 / 完成报告 / 决策 / 人工台账
```

---

> 🔴 **v2.6 核心推进铁律**：
> 1. **一次只写一个 Phase**：严格串行推进。当前 Phase 施工、验收、完成报告、回写、撰写者复核全部完成并满足出口条件后，才允许撰写下一 Phase 施工蓝图。严禁提前批量生成后续阶段蓝图。

> 3. **台账是唯一载体**：继续保留单文件台账，绝不新建分散的「功能验收.md」等平行文件。

## 二、经验库怎么读（**只有一份，通读一次**）

| 文件 | 放什么 | 怎么读 |
|---|---|---|
| [BLUEPRINT-经验库.md](BLUEPRINT-经验库.md) | **唯一经验库**：P 判据 / B 边界 / V 验证 / C 变更 / R 报告 / H 人在环 / I 基础设施，七类 106 条 | **写蓝图前通读一次**（约 2 万字符）；之后按 **§0 六问自检** + **§8 场景速查**回查 |
| [BLUEPRINT-经验库-全量台账.md](BLUEPRINT-经验库-全量台账.md) | 旧版 186 条 R 台账 + `文件:行号` 出处 | **只用于考古 / 溯源**，不参与日常读取 |

**为什么收敛成一份**：旧版拆三份（通用 / 具体坑 / 全量台账，33 万字符），并设计成「按角色取最小必读集」。
实测结果是——**agent 在任务中途不会回头翻库**，于是「库越大越全」换不来效果，只换来上下文被吃掉一半。
现在的第一要求是**能一次读完**，不是**能查到一切**。

**分级判据（自评问句）**：

```
这条错在「判据本身」吗？           → P
错在「边界 / 完整性单位」吗？       → B
错在「尺子 / 对照物 / 数据源」吗？   → V
错在「顺序 / 传播面 / 不可逆」吗？   → C
错在「数字 / 文档 / 产物留痕」吗？   → R
错在「人该不该做 / 做多少」吗？     → H
核心是某条命令 / API 的行为吗？     → I（换栈必须重新实测）
```

> ⚠️ **I 类条目里的命令与 API 结论只在那套技术栈成立**；换栈后只带走形状，重新实测。

## 四、三点须知

1. **本包不含任何指向包外文件的链接**：跨目录引用一律是相对路径（`methodology/…`、`../task-<任务名>/…`），
   任务侧的文件用**占位符**，引用历史记录只写「记录标识」。因此 `methodology/` 可以直接转发，
   也可以整份拷到任何任务旁边——**不会因为换目录而断链**。
   ⚠️ 例外：少数「环境类」条目含**原机器的绝对路径**（如 `D:\data\node24\npx.cmd`），那是历史记录原文，**当举例看、不要照抄**。
2. **经验条目自身是完整的**（错误做法 / 症状 / 根因 / 正确做法 四段齐全）。
   出处只承担"溯源"与"唯一标识"两个作用——不去解析它，经验库照样可用。
3. **要迁移到你自己的项目**时：用规范 §1–§10 全部 + 经验库 P/B/V/C/R/H 六类全部 + I 类**只取形状**。
   I 类条目多为 Node / Electron / git / PowerShell 场景，**参考形状、别照抄命令结论**。
